## 二、服务端

```
/opt/quizassist-config/
├── index.js              零依赖 Node 服务
├── data/config.json      线上配置（后台保存直接改这个）
└── public/admin.html     网页后台单页
```

systemd 单元：`/etc/systemd/system/quizassist-config.service`

```ini
[Service]
WorkingDirectory=/opt/quizassist-config
Environment=PORT=18080
Environment=HOST=127.0.0.1
Environment=ADMIN_TOKEN=841117Dqc
ExecStart=/usr/local/bin/node /opt/quizassist-config/index.js
Restart=always
```

只监听 `127.0.0.1:18080`，外网一律走 nginx，端口不暴露。

常用命令：

```bash
systemctl status quizassist-config      # 状态
systemctl restart quizassist-config     # 改完 index.js 后重启
tail -f /var/log/quizassist-config.log  # 日志
curl -s http://127.0.0.1:18080/healthz  # 健康检查
```

## 三、nginx

改动只落在 `/etc/nginx/conf.d/xuhuohua.conf` 的 `server { server_name xuhuohua.xyz; }` 块内，
新增三段 location：

- `/quiz-api/admin/` → `127.0.0.1:18080/api/v1/admin/`（Basic Auth）
- `/quiz-api/` → `127.0.0.1:18080/api/v1/`（无鉴权，加 `Cache-Control: no-cache`）
- `/quiz-admin/` → `alias /opt/quizassist-config/public/`

**备份**：`/etc/nginx/conf.d/xuhuohua.conf.bak-quizassist-*`（改动前自动生成）。

### ⚠ 关于 `agent.py` 的坑（重要）

同目录下 `/opt/kebiao-site/deploy/agent.py nginx` 会用
`xuhuohua.conf.txt` **整份覆盖** `xuhuohua.conf`。

原来的 `.txt` 已经落后于线上（缺 10-17 那批 nbcc 子域 301），直接跑会把这些改动一起回退。
本次已经把**线上文件回写进 `.txt`**，所以现在再跑 `agent.py nginx` 不会丢 quiz-api 段。

以后你要改 nginx：

1. 改线上 `xuhuohua.conf`；
2. `cp /etc/nginx/conf.d/xuhuohua.conf /opt/kebiao-site/deploy/xuhuohua.conf.txt`；
3. `nginx -t && systemctl reload nginx`。

别只改 `.txt` 就期望生效（反了），也别只改线上就跑 `agent.py`。

## 三·五、使用统计

后台第二个页签「统计」，数据来自 `data/reports.ndjson`，服务端按需聚合（缓存 60 秒）。

| 指标 | 口径 |
| --- | --- |
| 独立设备 | 去重后的 `deviceId` 数量 ≈ 装过这个 App 的手机数 |
| 累计启动 | `app_launch` 事件总数 |
| 今日启动 / 今日活跃设备 | 按服务器本地时区（CST）的自然日切分 |
| 事件总数 | ndjson 里的有效行数 |
| 版本分布 | `versionName` 计数 |
| 近 30 天柱状图 | 每天启动次数 |

接口：`GET /api/v1/admin/stats`（经 nginx 是 `/quiz-api/admin/stats`），需要 Basic + `X-Admin-Token`。

统计会顺带读取最近 3 个滚动备份（`reports.ndjson.<ts>.bak`），换文件后历史不丢。

想清空统计：

```bash
systemctl stop quizassist-config
rm -f /opt/quizassist-config/data/reports.ndjson*
systemctl start quizassist-config
```

关掉上报：后台「功能开关」把 `enableReport` 取消勾选，客户端就不再发。

```bash
ls -l /opt/quizassist-config/data/

```

### 更新 APK 分发（含网盘）

小飞机网盘没有开放上传接口，前端请求带 `encryptHex` 签名 + 登录态 `userId`，
脚本没法直接往分享里塞文件。所以标准流程是「服务器直链先上、网盘手动拖一次」。

> 课表项目（`/opt/kebiao-site`）的「发版」也是同一结构：`admin_server.py` 的
> `/api/upload` 只负责把 APK 落到服务器，`MIRROR_URL`（网盘分享地址）是写死的常量，
> `/mirror` 只做 302 跳转 + 计数。网盘那份一直是人工放的，没有自动化。

1. **后台上传**（推荐）：进 `https://xuhuohua.xyz/quiz-admin/` → 「发版」→ 把 APK 拖进去。
   服务器边收边算 sha256，完成后自动回填 `downloadUrlAlt` 和 `apkSha256`。
   50 MB 约 30 秒。

   等价的命令行方式（脚本化时用）：

```bash
curl -u admin:841117Dqc -H "X-Admin-Token: 841117Dqc"      -H "Content-Type: application/octet-stream"      --data-binary @app-release.apk      "https://xuhuohua.xyz/quiz-api/admin/upload?filename=quizassist-2.5.8.apk"
```

   或者走 SSH 直接落盘（不经 nginx，最快）：

```bash
pscp -pw '<密码>' app-release.apk root@121.43.151.118:/var/www/quizassist/quizassist-2.5.8.apk
```

2. **拖进网盘**：登录 [小飞机网盘](https://www.feijipan.com/) → 打开目标分享 →
   上传 APK → 记住新的分享链接和提取码。

3. **回填后台**：`downloadUrl` = 网盘分享链接（主用），`downloadUrlAlt` 上传时已自动填好，
   `latestVersionCode` +1、写清楚 `updateContent`，保存。

这样用户点「去下载」走网盘（不限速），网盘抽风时点「直链下载」走服务器。

如果网盘支持「离线下载 / 链接导入」，可以直接把第 1 步的直链粘进去，
省掉本地再传一次 50MB。

新包上传（走 SSH，不占 nginx 带宽）：

```bash
pscp -pw '<密码>' app-release.apk root@121.43.151.118:/var/www/quizassist/quizassist-2.5.8.apk
```

直链立刻可用：`https://xuhuohua.xyz/quizassist/quizassist-2.5.8.apk`
（`/quizassist/` 由 nginx alias 到 `/var/www/quizassist/`，带 `Accept-Ranges`，支持断点续传。）

算哈希填进后台：

```bash
sha256sum app-release.apk
```

然后改后台「版本更新」里的 `latestVersionCode` / `downloadUrl` / `apkSha256` / `updateContent`。
`minSupportedVersionCode` 一旦调到高于某个旧版本，那批用户会被强制更新（没有取消按钮），慎用。

旧包不用立刻删，占一点磁盘而已；40G 盘当前用了 31%。

## 五、健康检查清单

```bash
# 1) 服务活着
systemctl is-active quizassist-config && curl -s http://127.0.0.1:18080/healthz

# 2) 外部可拉配置（含 ETag）
curl -sSI https://xuhuohua.xyz/quiz-api/client/config | head -8

# 3) ETag 生效（应返回 304）
ET=$(curl -sSI https://xuhuohua.xyz/quiz-api/client/config | tr -d '\r' | awk -F': ' '/^ETag/{print $2}')
curl -sS -o /dev/null -w '%{http_code}\n' -H "If-None-Match: $ET" https://xuhuohua.xyz/quiz-api/client/config

# 4) 后台鉴权正常（无密码 401，有密码 200）
curl -sS -o /dev/null -w '%{http_code}\n' https://xuhuohua.xyz/quiz-admin/
curl -sS -o /dev/null -w '%{http_code}\n' -u admin:841117Dqc https://xuhuohua.xyz/quiz-admin/

# 5) 证书还有效
echo | openssl s_client -connect xuhuohua.xyz:443 -servername xuhuohua.xyz 2>/dev/null | openssl x509 -noout -dates
```

## 六、为什么不给客户端用 IP 或子域名

- **裸 IP + HTTPS**：证书是 `CN=xuhuohua.xyz`，客户端用 `https://121.43.151.118` 会因
  主机名不匹配直接校验失败。
- **裸 IP + HTTP**：targetSdk 35 默认禁止明文流量，要额外开 `usesCleartextTraffic`，
  等于把整包所有请求都放开，不值得。
- **`quiz.xuhuohua.xyz` 子域名**：DNS 没有解析记录，且现有证书不含通配符
  （`game.xuhuohua.xyz` 当初也是因此只走 HTTP）。要上子域名得先加 DNS 记录、
  再 certbot 扩展证书，会动到现有续期链路。

所以最终走 `https://xuhuohua.xyz/quiz-api/` 路径：域名已备案解析、证书有效、
零额外配置，Android 不需要任何明文放行。
